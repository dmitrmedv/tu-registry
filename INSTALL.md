# Встановлення оптимізованої конфігурації Claude Code

1. Зроби резервну копію свого поточного `CLAUDE.md` і теки `.claude/`.
2. Розпакуй вміст цього архіву **в корінь** репозиторію (там, де `package.json`).
3. Погодь заміну `CLAUDE.md`. Нова версія коротша; предметні правила перенесені в `.claude/skills/business-domain/SKILL.md`.
4. Переконайся, що `.claude/launch.json` лишився твоїм локальним файлом — у цьому пакеті його немає і він не перезаписується.
5. Перезапусти Claude Code або почни нову сесію командою `/clear`.
6. Перевір `/context` та `/status`. Для перевірки Skills спробуй `/business-domain` або `/react-development`.

Пакет не містить `.env`, `node_modules`, `.git`, зібраних файлів чи сканів.

## Що змінюється

- Коротший `CLAUDE.md`; доменні правила завантажуються окремим Skill за потреби.
- Стиснуті, узгоджені з фактичним стеком Skills.
- Додані path-scoped Rules для frontend, backend і shared package.
- Доданий read-only subagent `code-reviewer`.
- Доданий `.claude/settings.json`, який забороняє Claude Read tool читати секретні `.env`, залежності, build artifacts, git history та завантажені скани.

Автоматичні Hooks навмисно не додані: у цьому репозиторії вони не дають очевидної економії токенів і можуть запускати форматування/тести частіше, ніж потрібно. Перевірки запускаються наприкінці логічного етапу.
